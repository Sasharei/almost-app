# Almost: UX review and Almost Pay

Дата: 30 сентября — 1 октября 2026. Проверены текущие изменения Almost 7.2.1 (127), iOS 26.5 и выделенный Android-эмулятор. Это отчёт о выполненных изменениях и фактическом покрытии, а не заявление о проверке каждого экрана во всех комбинациях.

## Что изменено

- Вернули доступный слайдер и точный ввод суммы на экране решения. Сумма сохраняет дробную точность, применяется к текущему решению, клавиатура закрывается кнопкой Done.
- Нажатие на ведущую карточку открывает решение. Видимая команда Edit card открывает полный существующий редактор: название, сумма, категория, описание, значок, цель, периодичность, копирование и удаление.
- Almost Pay показывает точную сумму и явно объясняет симуляцию. Сохранение, трата и пакетный сбор проходят подтверждение до изменения данных. Прогноз траты раскрывается отдельно. Отмена сохраняет карточку, введённую сумму и незавершённое решение.
- На настроенном устройстве один экранный запуск вызывает настоящую локальную биометрию ОС. Далее идут имитация обработки и успех с нативной тактильной обратной связью. Банковского платежа, вызова Apple Pay или покупки RevenueCat нет.
- Без настроенной биометрии и при явном выборе альтернативы остаётся двухэтапное экранное подтверждение. Отмена/ошибка сканирования автоматически успехом не считаются.
- Общие цели касания, уровни кнопок, модальные поверхности, доступность вложенных действий, длинные надписи, настройки, paywall, профиль и расширение паузы исправлены с сохранением обработчиков. Редактор больше не просвечивает поверх фона.
- Результат сохранения показывает сумму именно текущего решения. Гидратация статистики защищена от повторного суммирования при перезагрузке.

## Боковая кнопка: результат исследования

Для Almost Pay нет обычного публичного API подтверждения произвольного действия двойным нажатием кнопки питания iPhone. Apple предоставляет такой платёжный интерфейс через [NFC & SE Platform](https://developer.apple.com/support/nfc-se-platform) со специальным entitlement и соглашением; это не API для имитации платежа. [Тройное нажатие](https://support.apple.com/en-ie/111771) относится к системным функциям универсального доступа. Отдельная Action button поддерживает пользовательские App Shortcuts на соответствующих моделях; доступ к боковой кнопке для разговорных приложений в отдельных регионах не соответствует этому сценарию ([Apple Hardware interactions](https://developer.apple.com/documentation/appintents/hardware-interactions)).

В Android системная политика перехватывает KEYCODE_POWER и снимает ACTION_PASS_TO_USER ([AOSP Android 16](https://android.googlesource.com/platform/frameworks/base/+/android16-qpr1-release/services/core/java/com/android/server/policy/PhoneWindowManager.java)). Универсального обработчика двойного/тройного нажатия питания для этого приложения нет. Отслеживание блокировки и возврата приложения не используется как доказательство подтверждения.

Использован [Expo LocalAuthentication SDK 54](https://docs.expo.dev/versions/v54.0.0/sdk/local-authentication/): iOS Face ID/Touch ID; Android BiometricPrompt. При нескольких доступных способах Android выбирает способ сам, приложение показывает общее название биометрии. На Android нет Apple Face ID/Touch ID как технологий — используются лицо/отпечаток конкретного устройства. Скан и шаблоны биометрии приложение не получает.

## Проверка UX правил

| Правило | Результат изменений |
| --- | --- |
| Fitts | Минимальные области взаимодействия 44 pt iOS / 48 dp Android, большие подтверждения, доступный слайдер |
| Hick | Одна основная команда в фокусе и подтверждении; дополнительные параметры и прогноз раскрываются отдельно |
| Zeigarnik | Отмена оставляет незавершённое решение и его сумму; отмена пакетного сбора не удаляет записи |
| Jakob | Системная биометрия, знакомые формы редактирования, предсказуемые back/cancel |
| Goal-gradient | Сумма текущего решения и реальное движение к цели; этапы имитации не названы настоящим банковским переводом |
| Von Restorff | Основная кнопка выделена, альтернативы и отмена имеют другой визуальный вес |
| Miller | Сумма и данные карточки сгруппированы; прогноз и редкие действия отделены |

Пять принципов проверены для затронутых состояний: следующий шаг выделен; дополнительные действия доступны; уровни кнопок различимы; ограничения объяснены; отмена/ошибка/загрузка/успех имеют соответствующие действия. Инвентарь действий находится в PLAN.md. Статические проверки не считаются визуальным доказательством.

## Нативное покрытие

| Область | iOS | Android |
| --- | --- | --- |
| Today, Progress, Pause, Budget, Profile; основные переходы | Просмотрены | Просмотрены |
| Настройки: light, dark, PRO и все 6 акцентов | Скриншоты 8 вариантов | Скриншоты 8 вариантов |

| Almost Pay save: отмена и результат | 12.34 до биометрии; 6.00 без биометрии в финальной сборке | 12.34 и 7.89 до биометрии; 6.00 через системный отпечаток в финальной сборке |
| Almost Pay spend и раскрытие прогноза | Полная финальная проверка не выполнена | Dark: раскрытие/сворачивание, отмена; успешная трата 6.00 через отпечаток |
| Биометрия | Нативная сборка успешна; отсутствие настройки и экранный fallback проверены. Сам Face ID/Touch ID не проверен | Нативный BiometricPrompt: отмена → повтор → успех. Лицо на этом эмуляторе отсутствует |
| Premium Budget / Reports | Временный QA доступ: Budget Indigo, Reports Aqua просмотрены | Billing unavailable; настоящая покупка не проверялась |

Настройки во всех темах не означают проверку всех модальных окон в этих темах. Полной матрицы каждого экрана × темы × 11 языков × крупного шрифта × RTL × устройства пока нет. Не проверены все редкие цепочки, Android face, iOS biometric scan, физическое ощущение haptics и release-сценарии атрибуции/подписки. Управление меню Face ID в Simulator через CUA дважды ответило тайм-аутом; это конкретный пробел нативной проверки.

Android системный биометрический запрос отображает название Almost Pay, пояснение симуляции и команду Touch the fingerprint sensor. Его защищённое окно возвращает чёрный скриншот; содержимое проверено через нативную accessibility-иерархию. Скриншот чёрного окна не выдаётся за визуальное подтверждение.

Снимок данных после отмены: savedTotal 112.39, historyCount 11. После отпечатка: 118.39, historyCount 12, одна новая запись refuse_spend на 6.00. При последующей покупке той же карточки сохранён существующий механизм отмены её прошлых сохранений: savedTotal 104.50, новая запись spend на 6.00. Числа и наблюдения сохранены в checks/native-biometric-observations.json.

Тестовые финансовые данные и настройки восстановлены из исходных резервных копий на обоих выделенных устройствах. Временный Premium bypass удалён из App.js; реальные SDK entitlements не подменялись. Тестовый PIN Android снят. Другой проект и его симулятор не затрагивались.

## Проверки

- Functional parity: PASS, 178 контрактов, 1701 фрагмент поведения, 41 проверка достижимости. Исходные действия сохранены; новые подтверждения добавлены до записи результата.
- Localization: PASS для en/es/fr/ru/de/pt/it/ar/zh/ko/ja; тексты биометрии и Face ID permission покрывают все 11 языков. Native permission validator также PASS.
- Themes: PASS, light/dark/pro и шесть PRO акцентов. Фактическое визуальное покрытие описано выше.
- UI/session: 39 PASS; engagement: 125 PASS; attribution: 18 PASS.
- Analytics contract и native analytics config: PASS. AppsFlyer и единый серверный RevenueCat путь не изменены.
- Typecheck, ESLint (без ошибок, с существующими предупреждениями), security tests, backend tests (27), runtime parity и размер APK: PASS.
- Новые нативные debug-сборки iOS и Android: PASS, установлены на выделенные устройства.
- Полный npm run verify: FAIL на check:security-audit — девять существующих npm advisories. Остальные последующие gates запущены отдельно и прошли. Audit не отключён и не ослаблен.

Уязвимости, блокирующие verify: GHSA-m9gg-hp2v-232j, GHSA-f596-whhp-79r4, GHSA-q2hr-2g5m-vwhr, GHSA-qhr7-859c-m2p7, GHSA-6j4f-fj2g-mc7p, GHSA-6h2x-m376-mqjq, GHSA-3wwx-pv8p-q78v, GHSA-r53p-7pc4-xj5r, GHSA-rfgv-xxqx-mfg5.

## Другие обнаруженные ограничения

Существующие накопительные lifetime-метрики тестового Android профиля уже содержали завышенные исторические значения. Защита гидратации предотвращает новые повторные прибавления, но старые суммы не пересчитывались по неполной истории. Это отдельная задача миграции данных. Debug LogBox предупреждения RevenueCat billing и iOS notification keychain закрывались через UI; они иногда перекрывали цели автоматизации и не скрывались кодом приложения. Неуспешные тестовые попытки в flows/checks не считаются прошедшими сценариями.
