## iOS: сборка успешна, запуск заблокирован окружением

Текущий native Debug simulator build **BUILD SUCCEEDED**: workspace `ios/Almost.xcworkspace`, schemeAlmost, `ARCHS=x86_64 ONLY_ACTIVE_ARCH=YES CODE_SIGNING_ALLOWED=NO`, отдельный DerivedData, jobs3. Выполняемый файл x86_64. Установка в собственные iPhone17/iOS26.5 и iPhoneSE3/iOS17.0 успешна; запуск не состоялся. App UI на iOS в этом прогоне **не проверен**.

`simctl launch --arch=x86_64` возвращает FBS RequestDenied; launchd/system log содержит `Bad CPU type in executable`/EBADARCH. Контрольная системная команда `arch -x86_64 /usr/bin/true` также не выполняется, хотя `/usr/bin/true` содержит x86_64 slice. В `/Library/Apple/usr/libexec/oah` найден только RosettaLinux, обычный runtime отсутствует; receipt `com.apple.pkg.RosettaUpdateAuto` не найден. Это подтверждает отсутствие работающего x86_64 translation path на текущем хосте, но не объясняет, когда и почему окружение изменилось. Повтор через установленный обычный Xcode26.6 вместо выбранного Xcode27.1 beta также не запустил приложение. Ad-hoc переподпись только временной копии приложения результата не изменила.

Почему раньше работало: отчёт `qa/release-e2e-2026-10-08/REPORT.md` фиксирует x86_64/Rosetta на iOS26.1; этого runtime сейчас нет среди доступных (17.0,18.5,26.5,27.0,27.1). Старый app artifact уже отсутствует, поэтому его повторный запуск не выполнен. Другой сегодняшний отчёт `qa/premium-unlock-review-2026-10-16.txt` использовал Expo Go harness отдельных экранов, а не полное native-приложение. Исторические отчёты — контекст, не доказательство текущего запуска.

ARM64 slice текущего MLImage исследован локально: объект LC_BUILD_VERSION platform2 (iOS device), а не iOS Simulator. Поэтому простая смена ARCHS на arm64 не является готовым решением; библиотеки, функции и SDK ради обхода не удалялись. Rosetta не устанавливалась, лицензия не принималась, глобальный xcode-select не менялся. Для продолжения полного native iOS-прогона требуется рабочее окружение запуска x86_64 либо корректный ARM64 Simulator вариант зависимости. Причину изменения host environment следует выяснить отдельно; UI-регрессия приложения этим блокером не доказана.
