# Аудит производительности Almost

Дата: 5 октября 2026. Версия приложения: 8.0.0. HEAD: `160fd606bd2f9a41d8357d0bc014f166385ca6a8`.

Аудит выполнен по `/Users/sasarei/.codex/rules/APP_PERFORMANCE_AUDIT.md`. Проверено текущее рабочее дерево с уже существовавшими незакоммиченными изменениями, а не только HEAD. Код приложения не изменялся. Область: общий React Native код iOS/Android, запуск, Today/выбор карточки, история, аватар, paywall, Shopping Pause, локальное хранение, клиент монетизации и SQLite backend. Нативная отрисовка Android/iOS и web отдельно не измерялись.

**Вывод:** обнаружены конкретные операции и архитектурные риски, которые заслуживают профилирования. Зависания, FPS, время запуска, потребление памяти и ускорение не измерены. Приоритеты ниже — порядок проверки по потенциальному воздействию, а не рейтинг уже измеренных узких мест.

Симуляторы, эмуляторы и приложения на устройствах не запускались: проект требует отдельного разрешения пользователя. Нет baseline релизной сборки, реального пользовательского набора данных, заданного устройства и сетевых условий. Статические проверки не заменяют runtime/визуальную проверку.

## Findings и порядок проверки

### 1. P1: синхронный файловый I/O Shopping Pause на главном потоке iOS

Доказательство по коду:

- `ios/Almost/ShoppingBlocker.swift:14`: `methodQueue` — `DispatchQueue.main`; `run` синхронно выполняет переданную функцию.
- `ios/Almost/ShoppingBlocker.swift:150`: `sync` вызывает транзакцию, заменяет события и copy, применяет состояние.
- `ios/ShoppingBlockerShared/ShoppingBlockerStore.swift:57–75`: транзакция захватывает файловую блокировку, читает и декодирует JSON, затем кодирует и атомарно записывает файл. Запись производится и при неизменившемся состоянии.
- `src/shoppingBlocker/useShoppingBlocker.js:75–89`: после гидратации выполняются sync при изменении данных/copy, возврате приложения и каждые 15 секунд активного приложения. Таймер не ограничен открытым экраном Shopping Pause.

Потенциальное воздействие: главный поток может ждать файловую блокировку другого процесса/расширения и выполнять дисковую работу в момент нажатия или прокрутки. Периодическая работа затрагивает и другие открытые экраны на iOS. Факт выполнения на главном потоке подтверждён; длительность блокировки и видимые зависания не измерены.

Рекомендация: измерить main-thread stalls и длительность sync; затем рассмотреть последовательную фоновую очередь для безопасной части хранения, разделение чтения статуса и записи данных, пропуск идентичных записей. Проверить требования API Screen Time к потоку отдельно. Сохранить межпроцессную блокировку, атомарность, порядок операций, восстановление shields при ошибке и актуальность периодических переходов. Простое отключение таймера может сломать поведение и не является готовым исправлением.

### 2. P2: стартовый экран ждёт широкую гидратацию

- `App.js:51735–51736`: готовность стартового логотипа зависит от `fontsReady && startupHydrated`.
- `App.js:68103`: сначала читаются health/backup/tamagotchi.
- `App.js:68131–68234`: следующий пакет содержит 115 упоминаний `STORAGE_KEYS`, включая историю, ledger, challenges, rewards и множество настроек; далее выполняется большой синхронный разбор/нормализация данных.
- `App.js:70275`: `startupHydrated` выставляется в конце загрузчика. `App.js:68062` и `70368`: отдельно отложен разбор decision stats, но основная гидратация остаётся до готовности стартового состояния.
- `App.js:737`: на iOS/web регистрируются семь Inter начертаний; Android использует системный шрифт.

Потенциальное воздействие: время первого полезного экрана может зависеть от данных второстепенных функций. Два последовательных чтения подтверждены, но нельзя считать их независимыми или безопасно объединять без проверки восстановления coin balance. Наличие 115 ключей само по себе не доказывает медленный запуск.

Рекомендация: замерить отдельно чтение, JSON parsing, миграции, fonts и первый полезный render. Только затем разделить обязательные и необязательные данные по потребностям экрана. Сохранить health recovery, восстановление сессии, monetization/hard-lock prerequisites и исключить показ некорректных промежуточных сумм. AppsFlyer startup/install reporting не откладывать и не связывать с этой гидратацией.

### 3. P2: колесо выбора и поиск карточек создают все строки

- `src/components/DecisionCardWheel.js`: `Animated.ScrollView` с `entries.map`, отдельными animated nodes и PracticeTarget для каждой строки. Видны только три строки, но коллекция целиком смонтирована.
- `App.js:30818`: передаётся полный `decisionEntries`.
- `App.js:30831`: поисковый диалог использует `ScrollView` и `filteredDecisionEntries.map`.
- `App.js:30736`: фильтрация выполняется непосредственно в render; форматирование статуса каждой строки включает даты и локализованные подписи.

Потенциальное воздействие: стоимость render/native views растёт с количеством карточек, особенно у активного пользователя с большим пользовательским набором. Реальное количество строк и время render не измерены.

Рекомендация: профилировать 10/100/500 допустимых карточек, затем при подтверждённом росте использовать виртуализацию или ограниченное окно render с доступом ко всей коллекции. Сохранить snap, selected index, момент разблокировки формы после drag, поиск/add, accessibility increment/decrement, tutorial targets и выбор дальних элементов. Не сокращать доступный каталог ради скорости.

### 4. P2: секундные обновления состояния попадают в большой AppContent

- `App.js:49594–93934`: AppContent содержит 415 мест вызова `useState` по текстовому подсчёту. Это показатель области обновления, не измерение React commits.
- `App.js:53111`: секундный daily-summary countdown обновляет state AppContent только при показанном summary.
- `App.js:55798`: секундный таймер иммунитета питомца обновляет state AppContent при открытом питомце и активном иммунитете, даже когда отдельная подсказка не открыта.
- `App.js:52551`: минутный daily-summary tick в AppContent не проверяет активность приложения.

Потенциальное воздействие: изменение локального счётчика повторно выполняет тело большого компонента; это не означает, что все дочерние native views перерисовываются. Профиль React commits отсутствует.

Рекомендация: записать commit time при summary/pet и обычной работе, проверить inactive-state callbacks. При подтверждении стоимости локализовать часы в небольших компонентах/подписках, сохранить точный отсчёт по абсолютному timestamp, закрытие при expiry и обновление после возврата приложения. Не удалять напоминания и countdown ради снижения render.

### 5. P2: аватар сохраняется без ограничения пиксельных размеров

- `App.js:75663`: image picker задаёт `quality: 0.8`, но не задаёт предельные width/height и не выполняет последующий resize.
- `App.js:75532–75574`: persistAvatarUri копирует файл; fallback читает и пишет целый файл через base64.
- `App.js:49354`: один из основных вариантов отображения — 96×96 logical units.

Потенциальное воздействие: большая фотография может увеличить хранение, перенос данных и временную память; фактический native downsampling и decode memory не измерены. `quality` не задаёт максимальное количество пикселей.

Рекомендация: проверить изображение 12/48 MP и ошибки file/content URI. Создавать производную аватара с размером под максимальное отображение и pixel density. Сохранять нужный оригинал для других функций; не применять агрессивное уменьшение к OCR/доказательствам расходов. Проверить качество во всех темах и accessibility масштабах, миграцию старых аватаров и fallback.

### 6. Пробел release gate: успешная проверка размера использовала debug APK

`npm run check:release` завершился с кодом 0, однако `check-app-size.js` выбирает самый новый apk/aab/ipa по mtime и не исключает debug. В этом запуске проверен `android/app/build/outputs/apk/debug/app-debug.apk`: 48.1 MB / 45.9 MiB. Это результат проверки существующего debug артефакта, не размер текущей релизной сборки. Соответствие артефакта рабочему дереву не установлено.

Рекомендация: для релизных выводов указать точный релизный артефакт через `APP_SIZE_ARTIFACT`, связать его с revision/build configuration и отдельно проверить iOS/Android. В дальнейшем сделать gate различающим release/debug. Порог/базовую величину не ослаблять. В данном аудите gate не изменялся.

## Изображения: измеренные свойства файлов

Результаты чтения заголовков и размеров сохранены в [assets.json](assets.json). В `assets/` найдено 123 PNG/JPEG/WebP, суммарно 42.88 MiB. Это полный каталог исходников; не размер установленного приложения, не объём одновременно загруженных картинок и не доказательство включения всех файлов в bundle.

| Используемый файл | Размер файла | Размер изображения | Теоретический один RGBA raster |
| --- | ---: | ---: | ---: |
| `assets/shopping-pause/hero.png` | 1,779,080 B | 1536×1024 | 6.00 MiB |
| `assets/paywall/v3/sky-hills.png` | 1,370,238 B | 1774×887 | 6.00 MiB |

Оба файла явно подключены в компонентах соответствующих экранов. RGBA оценка не является измерением реальной native памяти и не учитывает downsampling/буферы. Крупные mascot WebP следует проверять как анимации: нельзя заменять их одним кадром или оценивать всю анимационную память как один raster. Компрессия/ресайз hero — дополнительный кандидат с проверкой качества на high-density устройствах; подтверждённого runtime выигрыша пока нет.

## План недостающего runtime аудита

После разрешения на соответствующие запуски использовать реальные release builds на iOS и Android, сохранив AppsFlyer/RevenueCat release поведение. Зафиксировать build/revision, OS, устройство, частоту дисплея, font scale, язык, тему, сетевой режим и dataset; провести минимум 5 сопоставимых повторов каждого сценария, расширяя число запусков при высокой вариативности.

| Journey | Наборы/условия | Нужные измерения |
| --- | --- | --- |
| Первый запуск и возврат | Fresh install; returning user; история 0/200; cold/warm process; сеть/offline | Время до первого полезного интерактивного экрана, чтение storage, parsing/migration, fonts; успешная install attribution |
| Today / выбор / поиск | 10/100/500 допустимых карточек, в том числе дальняя строка и длинные переводы | React commit durations/counts, JS/UI frame time, задержка выбора/поиска, память, accessibility/tutor/search/add parity |
| Shopping Pause | Активная/неактивная сессия, периодический sync, competing extension operation | Main-thread stall, wait на lock, file read/write latency/count, энергонагрузка; правильные shields, unlock, cancel и recovery |
| Summary и питомец | Видимый countdown; expiry; app background/resume | Частота/cost commits, отзывчивость, верность time remaining и закрытия |
| Avatar / paywall | 12/48 MP photo; hero cold/warm; high density | Peak memory, decode latency, file size, качество, permissions/cancel/error |
| История и банковские расходы | History 200; несколько native pages; запись между страницами | First render, scroll frames, load-more latency, дубликаты/пропуски, сохранность delete/edit/filter/sort |
| Покупка/restore | iOS/Android release sandbox, сеть и retry | Request timing/dependencies, customer state correctness, revenue postbacks без duplicate client purchase |

Для конечного отчёта внести медиану/диапазон до и после каждого оправданного исправления, а также regressions и tradeoffs. Не отправлять личные суммы, содержимое сохранений или изображения в telemetry для сбора этих измерений.
