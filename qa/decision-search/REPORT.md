# Поиск и статусы в колесе решений

Проверка: iPhone 17, iOS 26.5, нативная Debug-сборка 8.0.0, текущий JavaScript. Использованы синтетические QA Coffee/Cigarettes/Snack/Taxi; у Snack последнее сохранение сегодня, у остальных — вчера. Следующая проверка назначена отдельно от факта выполнения сегодня.

Изменения:
- Строка поиска занимает первую строку над первой карточкой внутри ScrollView. Она прокручивается вместе с карточками и не перекрывает их.
- Поиск открывает существующий полный список с текстовым фильтром, клавиатурой и состоянием отсутствия результатов. «Посмотреть все» сохраняется. Закрытие не меняет карточку и сумму.
- Справа указаны следующая дата/время проверки либо отсутствие расписания, а также «Проверено сегодня» / «Ещё не проверено». Статус определяется по фактическим save/spend timestamps, а не по сбросу таймера.
- Убраны задержка 180 мс и блокировка действий до конца инерции. На iOS выбор обновляется по ожидаемой конечной позиции при отпускании пальца; финальная позиция уточняется после инерции. Повторная выборка того же ID не перезапускает ввод суммы. Прямой выбор останавливает старую инерцию.
- Смена карточки больше не сбрасывает прокрутку родительского экрана. Между сменой карточки и обновлением состояния суммы отображается сумма новой карточки, исключая кадр со старым значением.

## Runtime и визуальные доказательства

Проверено поиском: пустой результат, фильтр QA Snack, выбор результата с открытой клавиатурой, возврат через полный список, быстрый свайп с последующим открытием списка. QA Snack показывает галочку «Проверено сегодня», остальные — непроверенный статус. При выбранном Snack поиск визуально находится за верхним краем колеса. Проверка по accessibility-tree для скрытой строки не используется как визуальное доказательство: React Native сохраняет в дереве прокрученные элементы.

В light/ru проверены подписи, дата, переносы, выбранная строка, основные кнопки. В dark/en проверены те же поверхности и поиск с клавиатурой/пустым результатом. Ввод 17.5 сохраняется после закрытия списка. После свайпа 250 мс нажатие кнопки покупки открывает выбор категории для новой карточки. Это функциональная проверка последовательности; инструмент не измеряет задержку кадра и не доказывает отсутствие всех пропущенных жестов.

Скриншоты и журналы: `qa/artifacts/decision-search/`, основные прогоны `2026-10-02_234636`, `2026-10-02_235052`, `2026-10-02_235157`, `2026-10-02_235256`.

## UX и проверки

Главное действие в решении — запись накопления, покупка и поиск вторичны. В поиске главное действие — выбор результата; при пустом результате доступно исправление запроса и закрытие. Клавиатура не перекрывает результаты. Проверены семь UX-принципов: доступные цели нажатия, ограниченный набор решений, сохранение ввода при отмене, привычный поиск, честный статус выполнения, различимая основная кнопка и группировка контекста на карточке. Новых загрузочных/сетевых состояний нет: поиск локальный.

PASS: functional parity (198 контрактов), локализация (11 языков; 3 новых ключа), темы (light/dark/pro, 6 акцентов), typecheck, lint (0 ошибок, прежние 445 предупреждений), attribution/cloud/UI/engagement tests, security/backend tests и release parity/size. `npm run verify` останавливается на прежних 10 advisory npm audit; последующие этапы проверены отдельно.

Ограничения: PRO и его акценты не проверены визуально — тестовый аккаунт возвращает бесплатную тему. Android, компактный экран, VoiceOver/TalkBack, увеличенный шрифт и RTL не прогонялись. Текущие debug-предупреждения expo-notifications не исправлялись. Исходные данные симулятора восстановлены после теста; изменения касаются исходников приложения.
