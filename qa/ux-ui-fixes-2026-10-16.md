# Исправления UX/UI — iOS и Android, 16 октября 2026

Обновление 17 октября: запуск iOS восстановлен, выполнен дополнительный native visual review; см. [новый итог](ios-launch-visual-2026-10-17.md). Ниже сохранён результат предыдущего этапа.

Основание: `ux-ui-design-audit-2026-10-16.md`. Apple Design, пять UX-принципов и семь правил применены к затронутым состояниям. Предшествующие изменения рабочего дерева сохранены; attribution, SDK startup, consent persistence и purchase/restore/manage handlers не менялись.

## Изменения

- **UI-01:** AccessiblePressable со статическими стилями сразу меняет opacity при press-down. Pressable сохраняет onPress на release, отмену, refs, children-render-function, disabled и пользовательские state styles. Hit area не масштабируется.
- **UI-02:** непрозрачные control/filter-поверхности получили лёгкий диагональный SVG-градиент через уже используемый react-native-svg. Начальный semantic tint сохранён; второй endpoint удаляется по яркости от указанного foreground, не снижая его contrast ratio. Явный `foregroundColor` доступен для нестандартного текста. Reduce Transparency сохраняет однотонную поверхность. Полупрозрачные семантические tints и их стабильный фон не изменены; существующие SwiftUI/glass и fallback остаются. Бесплатная кнопка Reports в Profile стала открытым вторичным действием с тонкой границей.
- **UI-03:** paywall, Automatic Expenses и Shopping Pause выбирают fade при Reduce Motion. Общий App Modal обрабатывает эту настройку и для native, и для in-tree окна, включая выбор карточки; существующий Android transparent-host path сохранён.
- **UI-04:** edge-back отслеживает движение видимого содержимого, сохраняет текущую позицию при прерывании возвратной пружины, передаёт release velocity в возврат без отскока и восстанавливает экран при cancelled/failed/termination. Navigation вызывается на release; ведущая сторона зеркалится для RTL. Native recognizer передаёт progress/isRTL, старые native shells используют JS fallback. Используются существующие JS thresholds; native distance/vertical slop согласованы с ними. Кнопочные back/cancel и маршруты сохранены.
- **UI-05:** «+» решения помещён в строку заголовка внутри scroll content, с исходным creation callback и Keyboard.dismiss. Global goal shortcut в overview Progress перенесён в верхний rail, для которого зарезервированы высота/ширина заголовка; он не закрывает текст недельной карточки. На узких viewport≤390dp у Today primary CTA зарезервирован правый gutter под quick-actions FAB: отдельные области касания не пересекаются. Short/long press и меню глобальной кнопки сохранены. Другие дополнительные перекрытия плавающего chrome во время прокрутки требуют повторной визуальной оценки.
- **UI-06:** Settings и inline preferences зеркалятся через RTL direction без второго row-reverse. Общий AppText изолирует Android paragraph layout от повторного зеркалирования физического textAlign в Fabric TextLayoutManager; Arabic shaping и RTL-порядок родительских строк сохраняются. Верхние help/report/add и goal shortcut имеют зеркальную физическую позицию. Today header резервирует место для целей касания; Profile chevrons и back решения соответствуют языку. Для стрелок применены SVG-path вместо Unicode-глифов, которые bidi мог повторно зеркалить. На iOS учитывается язык независимо от LTR-настройки корневого shell. Существующие строки локализованы, новых ключей/текстов не добавлено.

## Состояния и действия

Today overview: основное действие — перейти к решению, secondary — добавить/справка/отчёт. Focus: primary — slider решения; secondary — потратить, отложить, изменить, выбрать/добавить карточку, назад. Выбор карточки: select, search и Done сохранены. Progress empty/populated: создать/открыть цель; secondary — rewards, insights, budget, subscriptions и остальные разделы. Profile free/premium: full access/reports остаются доступны с разной важностью; Settings сохраняет переключатели и все списки выбора. Paywall/Expenses/Shopping Pause: primary и все loading/error/retry/disabled/close handlers сохранены; изменён только вид перехода. Для жеста отдельно проверены короткий ход, противоположное направление, RTL, release и прерывание.

## Проверки

- `npm run check:functional-parity` — PASS до редактирования (254 контракта) и после (258 контрактов, 2190 fragments, 45 reachability patterns). Действия не удалялись; контракт inline creation обновлён на эквивалентный callback.
- `npm run check:localization` — PASS, все12 языков и native permission/shortcut checks. Новых/изменённых продуктовых строк нет; decorative arrows заменены SVG. Существующие переводы других задач сохранены.
- `npm run check:themes` — PASS, light/dark/PRO и6 акцентов. Численные regression tests сохраняют contrast ratio gradient endpoints относительно foreground.
- `node --test scripts/tests/ui-design-regressions.test.js` — PASS6: press forwarding/disabled, RTL release/cancel, theme contrast, interrupted spring/native callback race, явное направление forward/back SVG и Android RTL paragraph alignment.
- `npm run verify` — PASS, включая analytics/native configuration, unit suites, typecheck, lint, security/backend и release gates. ESLint:0 errors,434 существующих warnings; размер проверялся по старому debug APK, не по новой release-сборке.
- `xcrun swiftc -frontend -parse ios/Almost/LiquidGlassNativeViewManager.swift` — PASS синтаксиса; это не полная native-сборка и не runtime-проверка.
- `git diff --check` — PASS.

Android: свой read-only emulator5584, Android16/API36, 1280×2856/density480. Старый native debug shell build131 + собранный JS рабочего дерева. Synthetic local profile “UX Fix QA”, пустые цели/история; покупки/entitlements не подменялись. Из-за недоступного Billing development LogBox отключён только в временной копии bundle через `ignoreAllLogs(true)`, production source не менялся. Реальные SDK ошибки не объявляются исправленными.

Просмотрены native-resolution изображения Today, Progress и decision в light; Progress/decision и Settings в dark; Arabic Settings/Profile dark. FAB больше не пересекает weekly-note и строку Later в просмотренных состояниях light/dark. Нажатие inline «+» открывает реальную форму создания; hardware Back отменяет её, возвращая на решение. Для общих PlatformSurface/PlatformPressable отдельно от App просмотрены light/dark и6 PRO-акцентов (indigo/emerald/sunset/violet/aqua/gold); основное действие действительно вызывает handler. Это component-preview, не visual PASS всех PRO-экранов.

Контрольные снимки и состояния сверялись отдельно от Maestro assertions. Первые smoke attempts не дождались bundle, а preview при повторном запросе однажды отдавал старый module cache: исключены из visual coverage. Metro перезапущен и текущий код сверяется при финальном захвате. Попытки gesture-preview были перехвачены системным Android Back и закрыли harness; JS edge tracking/RTL/cancel подтверждены regression tests, но физическое поведение жеста не объявляется runtime PASS. Буквальные selector/precondition и parsing ошибки temporary flows не считаются продуктовыми дефектами.

Остаточные gaps: native iOS UI/SwiftUI/Liquid Glass и новый native recognizer не запускались из-за ранее установленного EBADARCH/x86_64 environment blocker и несовместимого ARM64 Simulator slice MLImage. Rosetta/SDK/production scanner не менялись. Full release E2E, покупки/restore/manage, все loading/error/permission состояния, PRO whole screens и полная Dynamic Type/locale matrix не проверены. Статические проверки не являются визуальным PASS. Финальный bundle сверён на наличие исправленного Android paragraph direction, SVG-chevron, theme binding и CTA gutter. После его загрузки повторно просмотрены compact Today top/scroll/CTA, Profile Settings target и Settings Arabic dark при360×640dp, system font_scale1.6 (существующие maxFontSizeMultiplier компонентов сохраняются). Бренд отделён от верхних контролов; primary CTA и coin FAB имеют раздельные области; Arabic заголовки/подписи выровнены справа, SVG-back смотрит вправо, forward-chevron — влево. Реальный переход Profile→Settings подтверждён и изображением, и assert; flow завершён exit0. Предыдущая попытка нажала строку, оказавшуюся под нижней навигацией; повтор с centering target в viewport прошёл. Это не доказательство поломки роутинга.

Это не полный прогон обеих платформ. Остаточные unverified состояния выше не переводятся в PASS.

Performance: добавлены только небольшой SVG на control/filter и Animated translation при edge drag; release FPS/latency/memory до/после не измерены. На перегруженном хосте debug startup timing не является performance evidence. Изображения, данные, сети, пагинация и startup infrastructure не оптимизировались; отсутствует измеренный bottleneck для таких изменений.
